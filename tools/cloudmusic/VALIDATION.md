# 验证记录与兼容边界

记录日期：2026-10-02。以下只描述已经完成的验证，不将一次成功启动等同于所有插件和版本都受支持。

## 真实客户端环境

| 项目 | 实测值 |
| --- | --- |
| Windows | Windows 10 专业版 22H2，10.0.19045，x64 |
| 网易云主程序 | 3.1.41.205529，AMD64 |
| libcef.dll | 91.2.3+g3268653+chromium-91.0.4472.169，AMD64 |
| BetterNCM | 官方 1.3.4 x64 DLL |
| PluginMarket | 0.8.4，应用本仓库补丁 |
| 可选插件 | RefinedNowPlayingNext 3.0.2，未修改上游代码 |

真实客户端验证于 2026-10-01 完成：

- 原生 API 与 JavaScript 框架均加载，BetterNCM 按钮、插件管理器和商店可见。
- 官方插件索引当时返回 82 条，其中 24 条声明兼容 3.x，商店页面显示 23 张插件卡片。这些数字是一次观测，不能作为当前库存或逐项兼容承诺。
- 插件下载返回 HTTP 200，下载样本有正确 ZIP 签名。
- 正常、不带调试参数的启动加载成功，临时诊断端口关闭。
- `cloudmusic.exe`、`libcef.dll` 安装前后 SHA-256 未改变。
- RefinedNowPlayingNext 完整重启后成功加载，已验证显示退出按钮、关闭和重开歌词页。20 秒观测中，100ms 定时器额外延迟约 0.1–2.4ms。

卡住问题没有稳定复现，也没有通过 GPU 开关对照确定因果。未实施长期播放、连续切歌或内存泄漏验证，因此不宣称修复了插件卡死的根因。

## 公开安装工具验证

2026-10-02 已通过：

- Windows PowerShell **5.1.19041.6456** 和 PowerShell **7.6.6** 的隔离文件操作测试。
- `-CheckOnly` 不写入；首次安装与回滚；已有配置保留和恢复。
- 遇到未知加载器拒绝覆盖；`-MarketOnly` 保留已有加载器。
- 回滚保留安装后的配置修改；检测到加载器后来被替换时拒绝回滚覆盖。
- x86 PE 头拒绝安装；发行包校验失败时拒绝安装。
- 指定插件禁用、重复禁用不重复写入、重新启用时保留其他禁用项。测试中将进程启动替换为记录器，未运行 PE 测试样本。
- PowerShell 5.1 在真实安装目录完成自动检测与只读预检，未重装或重启该客户端。

隔离测试使用伪造的最小 PE 头与临时目录，验证脚本文件行为，不代表该样本可以运行，也不代替上面的真实应用验证。

## 构建验证

从全新目录检出固定的 PluginMarket 提交，应用发行补丁和锁文件后，`npm ci --ignore-scripts` 与 `npm run build:prod` 成功。

解包后的 `main.js`、`manifest.json` 与附带发行包逐字节一致。整体 ZIP 因时间戳不同而有不同哈希，属于容器元数据差异。

构建仍输出三个上游 Sass 弃用警告，依赖安装也包含旧依赖弃用提示。未在本次修复中升级整个上游前端依赖树。

| 对象 | 当前状态 |
